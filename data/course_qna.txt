Q: How do I explain what an orchestrator agent is to a prospect?
A: The orchestrator is the top-level agent in a multi-agent system — it receives the user's request, breaks it into sub-tasks, and delegates them to specialist agents. In the course's own capstone, the Breakfast Advisor Agent is the orchestrator, coordinating a Calorie Counter, a Meal Planner and a Price Checker.

Q: How do I explain a handoff to a non-technical prospect?
A: A handoff is how one agent passes a task, along with its context, to another agent in a multi-agent pipeline — like one specialist handing a case file to another. It's the mechanism that lets an orchestrator delegate work to specialist agents rather than doing everything itself.

Q: What is tool calling, in simple terms?
A: Tool calling is an AI agent's ability to reach outside its own reasoning mid-conversation and use an external function — a live web search, a database lookup, a calculation — to get real, current information instead of guessing. It's how the course's capstone checks live ingredient prices instead of relying on stale training data.

Q: What is a system prompt?
A: A system prompt is the persistent instruction block that sets an agent's role, personality, and rules at the start of every session — it's what keeps an AI assistant behaving like, say, a nutrition advisor rather than answering random unrelated questions. The course covers this directly when building guardrails and agent instructions in Module 4.

Q: What's the difference between zero-shot and few-shot prompting?
A: Zero-shot means asking the model to do a task with no examples, relying entirely on what it already knows. Few-shot means giving it 2–5 worked examples in the prompt so it matches the exact format and reasoning style you want. Both are covered as core prompt engineering frameworks in Module 1.

Q: What does 'temperature' mean when someone brings it up in an AI conversation?
A: Temperature is a setting that controls how random or creative a model's output is — low temperature gives consistent, factual answers, high temperature gives more varied, creative ones. It's one of the OpenAI API parameters covered hands-on in Module 2.

Q: What's the difference between IaaS, PaaS and SaaS, if a prospect asks?
A: IaaS (Infrastructure as a Service) gives you raw compute and storage that you manage yourself, like a virtual machine. PaaS (Platform as a Service) gives you a managed runtime where you just deploy code and the platform handles the infrastructure. SaaS (Software as a Service) is fully managed software you use over the web with no infrastructure management at all, like an API endpoint. These come up in the AI-901 certification's cloud fundamentals content.
